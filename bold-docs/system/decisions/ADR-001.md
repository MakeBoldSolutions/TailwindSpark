# ADR-001: Named Theme Activation with data-theme and Dark Compatibility

## Status

Accepted

## Context

TailwindSpark already depended on `.dark` as a compatibility signal for dark-mode styling, but the project needed to support multiple interchangeable design systems rather than only a light/dark toggle. A baseline release also needed a theme activation mechanism that could scale without rewriting existing screens or shared components.

## Decision

Use `html[data-theme="<theme-id>"]` as the canonical named-theme selector and retain `.dark` as a derived compatibility signal for dark variants. Theme-aware runtime code applies both the named theme state and the dark-mode compatibility class so existing selectors continue to work during migration.

## Consequences

### Positive

- Supports multiple named design systems without forking page or component implementations.
- Preserves compatibility with existing `.dark` selectors during migration and future maintenance.
- Keeps theme activation centralized at the document root for predictable override behavior.

### Negative

- The runtime must keep `data-theme`, theme mode, and `.dark` synchronized.
- Some legacy dark-mode assumptions remain in the codebase and require ongoing compatibility discipline.
