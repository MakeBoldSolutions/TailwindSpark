# ADR-003: Pre-Paint Theme Bootstrap and Cache-Safe Rollout

## Status

Accepted

## Context

Moving from a simple dark-mode toggle to a named multi-theme runtime increased the risk of wrong-theme first paint and mixed old/new assets during service-worker-controlled deployments. The release needed a resilient activation path that preserved user preference restoration and avoided manual cache clearing after theme runtime changes.

## Decision

Apply persisted theme state before React mounts, initialize the runtime from the DOM state, and coordinate theme runtime changes with service-worker cache versioning and stale-asset recovery hooks. This keeps first paint aligned with the user’s saved theme and makes rollout behavior coherent after deployment.

## Consequences

### Positive

- Avoids visible wrong-theme flash on application startup.
- Preserves persisted theme choice through reloads and return visits.
- Improves recovery behavior when browser caches contain stale theme runtime assets.

### Negative

- Startup and service-worker behavior become coupled and require coordinated validation.
- Deployment verification must include a cache/version handshake rather than only a static asset smoke test.
