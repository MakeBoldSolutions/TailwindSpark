# ADR-002: CSS-First Layered Semantic Token Contract

## Status

Accepted

## Context

The repository needed a multi-theme platform that could express materially different visual languages while keeping application structure and logic unchanged. The prior token model mixed semantic aliases, raw palette values, and Tailwind configuration literals, which increased drift risk and made additive theme work harder.

## Decision

Adopt a layered token model composed of reference tokens, semantic aliases, theme override blocks, and component recipe tokens, with `packages/design-tokens/theme.css` and Tailwind v4 `@theme` serving as the canonical source of truth. Shared primitives and app-owned surfaces consume semantic and component tokens rather than palette-specific classes.

## Consequences

### Positive

- Makes new themes additive instead of requiring duplicated component logic.
- Aligns the repository with CSS-first Tailwind v4 design-token practices.
- Reduces drift between shared design-token definitions and consuming surfaces.

### Negative

- Theme token completeness must be validated explicitly to avoid partial or broken themes.
- Existing tests that assert raw classes become less stable and require migration toward semantic expectations.
